## Security (builder-security)
- 2026-11-22 · builder-security · Verified httpx **0.28.1** and httpcore **1.0.9** (PyPI and the docs at python-httpx.org/advanced/extensions and encode.io/httpcore/network-backends, plus the installed source). The guard uses only httpx and the stdlib. No dnspython: `loop.getaddrinfo` is the default resolver and can be injected for tests.
- 2026-11-22 · builder-security · IP pinning: the request goes to the checked IP literal, with `Host` set to the hostname and the `sni_hostname` extension set, so TLS still verifies the hostname. Defence in depth: the httpcore network backend refuses any non-IP or disallowed connect.
- 2026-11-22 · builder-security · httpx 0.28.1 does not expose `network_backend`, so `security/http.py` replaces the private `AsyncHTTPTransport._pool`. `test_transport_pool_uses_guarded_backend` pins this, so an httpx upgrade fails loudly.
- 2026-11-22 · builder-security · httpcore 1.0.9 ignores `sni_hostname` inside CONNECT tunnels (it uses the origin host). So in proxy mode the client keeps the hostname and pre-checks each hop, and the egress proxy re-resolves, re-checks and pins.
- 2026-11-22 · builder-security · If any record in a DNS answer is disallowed, the whole host is blocked, so a mixed public and private answer cannot win.
- 2026-11-22 · builder-security · Non-canonical numeric hosts (decimal, octal, hex, short forms such as 127.1) are always blocked, even when they decode to a public IP. Legitimate links don't use them.
- 2026-11-22 · builder-security · Userinfo (`@` in the authority) is always blocked, even for public hosts.
- 2026-11-22 · builder-security · Ports 80 and 443 are allowed for either scheme. Every other port is blocked.
- 2026-11-22 · builder-security · `fetch()` allows only GET and HEAD, because the checker never submits anything. 303 changes the method to GET.
- 2026-11-22 · builder-security · Special-use and internal suffixes are blocked: localhost, local, internal, lan, home.arpa, test, example, invalid, onion, svc, cluster.local and others, plus every single-label name. The `falcon-demo-bank.test` fixture needs an explicit `GuardPolicy(allow_hosts=...)`, or `FL_EGRESS_ALLOW_HOSTS` on the proxy, and production leaves that empty. An allow-listed host may resolve to private, ULA or CGNAT addresses at every layer (URL, socket, proxy), but never to metadata, loopback, link-local or reserved addresses unless the exact IP is also in `allow_host_ips` (PR-4 review, item 1).
- 2026-11-22 · builder-security · IPv6-embedded IPv4 (mapped, 6to4, NAT64 64:ff9b::/96, IPv4-compatible) is unwrapped and judged as IPv4. Unwrapping can only make a decision stricter: IPv4-compatible `::a.b.c.d` with a public inner address is still blocked as reserved, because it isn't routable. Teredo and other 2001::/23 addresses, plus anything outside 2000::/3, are blocked.
- 2026-11-22 · builder-security · A body over max_bytes (hard cap 5 MB, after decoding) raises `SSRFBlocked(response_too_large)` instead of being truncated. Only gzip and deflate are requested and decoded, with bounded zlib output, and any other encoding gives `FetchFailed(unsupported_encoding)`.
- 2026-11-22 · builder-security · The caller can lower max_bytes, max_redirects or timeout but not raise them: values are clamped to 5 MB, 10 and 6 s. Keep-alive is off, so every hop gets a freshly pinned socket.
- 2026-11-22 · builder-security · The `on_block(reason)` hook is per-client, with a process-wide default set through `set_default_on_block`. Hook exceptions are logged and swallowed. T-014 wires it to `fl_ssrf_blocked_total{reason}` using `BlockReason` values as the labels.
- 2026-11-22 · builder-security · The guarded client sends straight to the transport, not through `httpx.AsyncClient.send`. The client's redirect builder raised a raw `httpx.InvalidURL` on a malformed `Location` (PR-4 review, item 2), and going direct also rules out cookies, auth and environment proxies.
- 2026-11-22 · builder-security · `GuardedHTTPClient.post()` exists only for the reputation APIs. It requires https, an exact host in `GuardPolicy.post_allow_hosts` (empty by default; otherwise `method_not_allowed`), a JSON or form body of at most 64 KB (`request_too_large`), the same pinning as `fetch()`, and it never follows redirects (a 3xx is returned). The `BlockReason` value `method` became `method_not_allowed`.
- 2026-11-22 · builder-security · The egress proxy (`services/egress`) uses `falcon_core.security` (one implementation). For CONNECT it calls `resolve_host_port` and dials the checked IP. For absolute-form `GET|HEAD http://…` it calls `validate_url` and `resolve_and_check`, dials the IP, and forwards one origin-form request with Host rebuilt from the checked URL and `Connection: close`. Other methods get 405, request bodies and obs-fold get 400, absolute-form https and denials get 403 with `X-Falcon-Block-Reason`. `fl_ssrf_blocked_total{reason}` is exposed on :8081/metrics.
- 2026-11-22 · builder-security · In proxy mode the client maps a proxy 403 (the plain-HTTP `X-Falcon-Block-Reason` header, or a refused CONNECT) to `SSRFBlocked`, with reason `egress_denied` when the reason is unknown.
- 2026-11-22 · builder-security · The egress image installs only `falcon_core/__init__.py`, `py.typed` and `security/`, plus hash-pinned wheels from `services/egress/requirements.lock` (httpx 0.28.1, httpcore 1.0.9, h11 0.16.0, anyio 4.16.0, idna 3.20, certifi 2026.11.20, typing-extensions 4.16.0; these match uv.lock).
