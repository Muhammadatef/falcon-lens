## Blocking

**B1. The egress proxy's SSRF denial is now a "soft render failure", so it yields `no_warning_signs`.**
- Where: `cascade/engine.py:74-79` (`SOFT_RENDER_FAILURES` includes `egress_blocked`, `egress_error`) and `:640-645`.
- The egress proxy denies with `403 Forbidden`, `X-Falcon-Block-Reason: <reason>`, `Content-Length: 0` (`services/egress/src/falcon_egress/main.py:89,99`).
- The sandbox maps any empty, content-type-less 403/405/407 via the proxy to `egress_blocked` (`services/sandbox/src/falcon_sandbox/policy.py:96-106`), and a CONNECT tunnel failure to `egress_blocked` (`:84-86`).
- So the second SSRF layer (DNS rebinding past the T0 guard, private-range answers at connect time) now ends in "no warning signs" whenever T1 is below tau_low.
- Your `e85669a` removed "Egress/SSRF blocks ... always degrade" from SCORING §4. The PR body still says "SSRF/policy blocks (...) still degrade", which is not true for this layer.
- `test_cascade_sandbox_shape.py::test_headless_refusal_is_soft_but_policy_block_degrades` locks the behaviour in.
- **Fix:**
  - The sandbox reads `X-Falcon-Block-Reason` and reports `blocked_by_policy:<reason>`, which always degrades.
  - Only an upstream empty 403 (no proxy header) may be a separate soft code, e.g. `http_403_empty`.
  - Add a test that drives the real `proxy_refusal` with the proxy's header.

**B2. Cloaking evasion: a phishing page that refuses headless browsers on a clean-looking domain is reported as `no_warning_signs`.**
- Probe `cloak52b.py`, invented hosts with p_clf below tau_low:

| host (invented) | renders a Falcon Demo Bank password+OTP page | same host returns empty 403 / TLS error / timeout |
|---|---|---|
| `oasisdentalclinic.ae` | suspicious 63 | #47: suspicious 8, degraded. **#52: no_warning_signs 8, not degraded** |
| `desertroseflowers.com` | suspicious 71 | #47: suspicious 11, degraded. **#52: no_warning_signs 11** |
| `greenvalleyplumbing.com` (p >= tau_low) | dangerous 95 | both: suspicious 49, degraded (gate holds) |

- `blocked_by_policy` still degrades in both, which is correct.
- Contract invariant 4 holds in the letter: the verdict is not `degraded`, because "degraded" was redefined. It fails in intent: the page was never seen and the user is told no warning signs were found.
- Compromised small-business sites and cheap clean-looking domains, plus bot-blocking kits, are the common case, not an edge case.
- The gate in `_t1_risky` (`engine.py:612-617`) ignores `domain.*`, so a freshly registered domain with no URL lexical flags also passes.
- **Fix** (general, no host lists):
  - A soft render failure may end in `no_warning_signs` only with affirmative, page-independent trust evidence. For example `domain.age_days` present, not errored and above the "established" threshold SCORING already uses (the `> 3650` trust row), or `registry.verified_official`.
  - Otherwise `suspicious`, with `confidence: low`, the reason "we could not open the page", and `degraded=true`.
  - This keeps x.com/tripadvisor-class sites (old domains) clean and closes the zero-day path.
  - Add `domain.*` risk to `_t1_risky`.
  - Add a test with a young-domain stub plus `egress_blocked`. It must not be `no_warning_signs`.
- The same applies to the T0 `dns_failure`/`dns_timeout` path (`engine.py:428-437,565-570`). DNS-level cloaking (an authoritative server that does not answer our resolver) should not buy "no warning signs" for an unknown domain.

**B3. Unknown sandbox error codes fail open.**
- `engine.py:631-633`: `raise SandboxError(err if err in known else "render_failed")`. Any code not listed (a new sandbox error, an internal failure string) becomes `render_failed`, which is soft.
- `http_502` is also in `SOFT_RENDER_FAILURES`, but `ports.py:63` raises `http_<status>` for the sandbox service's own HTTP errors. A failing sandbox or gateway therefore counts as "page refused us".
- That contradicts SCORING §4 "an unreachable sandbox and internal errors always degrade".
- **Fix:** default unknown codes to degrade, and keep the soft set to codes that only the browser-to-target leg can produce.

**B4. The held-out numbers are development numbers, and the test split was run during development.**
