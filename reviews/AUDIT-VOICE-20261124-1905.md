## Findings

### P0

**P0-1. Silence and background noise are transcribed as the wake phrase (false wake). Layers 4, 10. FIXED in the PR.**
- Evidence (live stack, 18:49):
  - `silence.wav` (3 s of digital silence) -> `{"transcript":"Falcon Lens.","lang":"en","wake":true,"intent":"none"}`
  - `noise.wav` (3 s pink noise) -> `{"transcript":"عدسة الصقر. هاي فالكون.","lang":"ar","wake":true,"intent":"off_topic"}`
  - `loudnoise.wav` (3 s white noise) -> `{"transcript":"عدسة الصقر.","wake":true,"intent":"none"}`
- Cause: Whisper echoes its decoding prompt («يا صقر. عدسة الصقر.» / "Hey Falcon. Falcon Lens.") when there is no speech, and the prompt is the wake phrase. Whisper's own no-speech score does not help: mlx-whisper reported `no_speech_prob 0.0` and a confident `avg_logprob` (-0.21 to -0.26) for all three clips. The existing `echo_guard` only looks at the compression ratio (0.6-0.65 here, far below its 2.4 limit).
- Impact: in a room with applause, air conditioning or crowd noise, the assistant wakes by itself, says "I'm listening", or plays an off-topic redirect nobody asked for. On a stage, after a hook video, this is the most likely way the demo looks broken. The browser VAD reduces how often noise is uploaded but does not stop it (see P1-3).
- Fix (three independent layers, all deterministic, in `packages/falcon_core/src/falcon_core/voice/guard.py`, used by both engines):
  1. **Signal gate before Whisper**: speech is bursty, noise is flat. Ratio of loud (p95) to quiet (p10) 20 ms frame energy must be at least 2.5 and the loud level above -50 dBFS. Measured: silence 0, pink noise 1.7, white noise 1.1, tone 1.0; clean speech 12-150; speech at 10 dB SNR 4.1-5.0; at 6 dB 2.9-3.3.
  2. **Prompt-echo guard**: a transcript made only of prompt words that holds more than one wake phrase (4+ words, or both scripts) is dropped.
  3. **Sparse-transcript guard**: 3 words or fewer out of more than 2.5 s of unbroken sound is dropped (a real "Hey Falcon" has 0.5 s of voiced sound).
- After (patched engine, scratch port): silence, pink noise, white noise, 16 s tone -> empty in 35 ms; modulated noise -> empty; all 10 speech clips, including Arabic mixed with pink noise, unchanged.
- Residual risk, stated plainly: noise that is bursty like speech, shorter than 2.5 s, and that Whisper turns into exactly one wake phrase still wakes it. A real second voice saying the wake phrase also wakes it (by design). The 2.5 threshold was chosen on synthetic mixes only; speech quieter than about 5 dB above steady noise is now ignored rather than guessed at.
- Owner: Fable (PR), Opus review, L1 merge. **After merge the native engine must be restarted** (`make voice-native-stop && make voice-native`) and the `api`, `voice` and `web` images rebuilt; the live stack still runs the old code.

### P1

**P1-1. The hook-video sentence gets the off-topic redirect. Layer 5. FIXED in the PR.**
- Evidence: `analyse("Hey Falcon, someone called saying he is from the bank")` -> `off_topic`; same for «يا صقر، واحد اتصل علي يقول انه من البنك». Live: `en_bank2.wav` -> `"intent":"off_topic"`. It only worked when the speaker also said "code"/«الرمز».
- Impact: the video is about an SMS plus a "bank" call. The natural first question on stage is answered with "That's outside what I do."
- Fix: one more alternative on the existing `otp` rule (a caller word plus a "from the bank" claim phrase) -> `faq.otp` ("Your bank never asks for your one-time code... even if they say they are the bank."). No new clip, no content change. "Should I call my bank" does not match (tested).

**P1-2. The FAQ fallback silently dies after two idle minutes. Layers 5, 10. FIXED in the PR.**
- Evidence: `curl localhost:11434/api/ps` at 18:48 listed no embedding model; first embed call took 6.07 s; `expires_at` was 2 minutes after the call. `faq_semantic.py` gives the call 0.4 s and sent no `keep_alive`. No metric or log recorded the miss.
- Impact: any question phrased outside the keyword rules, asked after a pause (for example after the video), gets the redirect. Nobody would know why.
- Fix: `keep_alive` on every embed request (`FL_VOICE_EMBED_KEEP_ALIVE`, default 24h); a background ping at the start of each utterance when the last success is older than 60 s; a forced background reload after a timeout; one reused HTTP client; `fl_voice_faq_semantic_total{outcome}` and the alert `VoiceFaqSemanticDegraded` with a runbook entry.
- Residual: the first question after an Ollama restart or eviction can still miss once. Ollama may still evict under memory pressure (a 25 GB chat model was loaded beside it).

**P1-3. VAD noise floor freezes while recording. Layer 1. NOT fixed (UI builder's files). Owner: L1 to route.**
- Evidence: `web/lib/vad.ts:128-131` updates `floor` only when no recorder is active. Once sustained noise crosses the threshold, `lastVoiceAt` keeps refreshing and the capture runs to `maxMs` (12 s), then starts again. Code read only; not reproduced in a browser.
- Impact: in a loud room each cycle uploads a 12 s clip and the microphone is deaf to the wake phrase meanwhile. With P0-1 fixed these clips come back empty in milliseconds, so this is now a responsiveness problem, not a false-wake problem.
- Fix: keep adapting the floor (slowly) during a capture, or end a capture whose level never dips.

**P1-4. No visible "thinking" state between end of speech and the answer. Layer 8. NOT fixed (UI). Owner: L1 to route.**
- Evidence: `web/components/VoiceAssistant.tsx` `sendUtterance` pauses the listener and awaits the fetch; `setPhase("heard")` happens only inside `onWake` (line 454), after the reply. For 0.5-1.8 s the page still reads "listening" while it is not.
- Fix: set a "processing" phase as soon as `onUtterance` fires and clear it on the reply. The owner asked for visible thinking progress; this is the gap.

**P1-5. A refused clip is announced as "voice unavailable". Layers 2, 8. Route half FIXED in the PR; UI half NOT fixed. Owner: L1 to route.**
- Evidence: live, `long.wav` (16 s) -> the API said 422 too long, the web route returned `502 {"error":"not_connected"}`. `voiceFailed` treats every non-200 the same: failure streak, spoken "unavailable" clip, back-off; after two, the paste box opens. A 429 also counts as a failure.
- Fix in the PR: the route now passes 422 (this clip was refused) and 503 with `Retry-After` (engines down) through.
- Still needed in the UI (one line each): on 422 go back to listening without counting a failure; on 429 wait without speaking.

**P1-6. The native engine does not survive a reboot or logout. Layers 4, 10. NOT fixed (owner decision).**
- Evidence: `launchctl list | grep falcon` shows only `ae.falconlens.localworker`; the engine is a `nohup` child started 17:01. `docs/RUNBOOK.md:43` documents the launchd install and says no make target does it.
- Impact: after a restart of the Mac Studio the assistant runs on the container engine (slower) until someone runs `make voice-native`. `VoiceNativeEngineDown` would fire, but only after container traffic.
- Fix: add `make voice-native-status` to the demo-morning checklist, or install the documented launchd plist. Installing a service is an owner decision.

**P1-7. Engine time budgets exceeded the web route's abort. Layer 3. FIXED in the PR.**
- Evidence: `SttRouter` used one 25 s client timeout for each engine; `web/app/api/voice/route.ts` aborts at 20 s. A hung native engine meant the page got a 502 before the container was ever tried.
- Fix: native 6 s, container 12 s (sum under 20 s, pinned by a test); a timeout parks the engine and is counted in `fl_voice_engine_failover_total{engine,reason}`; a 200 that is not an STT reply now falls through to the next engine instead of raising a 500.

### P2

- **P2-1. Web limit was 20/min, the API and `docs/PRIVACY.md` say 30.** A presenter talking beside the microphone produces roughly 12-20 clips a minute (estimate from sentence length, not measured). Flipping it is a privacy-claim change: owner/L1 decision.
- **P2-8. `faq.data_stored` claim.** "Your voice is processed on our own server and isn't kept" matches the voice code. "Your message text isn't kept unless you choose to report it" was **not** checked against the check/report storage code in this audit: `unverified`.
- **P2-9. Whisper word-joining in Arabic.** `ar_bank.wav` came back as «البنكويبي» (two words fused). The rules match stems inside tokens, so the intent was still right; noted in case a caption shows it.

### Client change for L1 / the UI builder (PR #135 owns `VoiceAssistant.tsx`)

In `sendUtterance`, replace the bare `fetch("/api/voice", ...)` and the `!res.ok` branch with:

```ts
const out = await postUtterance(form, { onRetry: () => void playKeys(l, [/* the "still checking" line */]) });
if (!out.ok) {
  setProblemText(voiceProblemText(out.reason, lang));           // shown, not spoken
  if (isClipProblem(out.reason)) return backToListening(token); // too long / unreadable: no failure streak
  if (out.reason === "rate_limited") { await sleep((out.retryAfterS ?? 4) * 1000); return backToListening(token); }
  return await voiceFailed(token, out.status);                  // unavailable / timeout / not connected
}
traceparent.current = out.traceparent;
const reply = out.reply;
```

`setProblemText` is a placeholder for however the page shows a message; the "still checking" clip key is the UI builder's choice.
