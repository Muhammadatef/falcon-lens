## Blocking findings

1. **B1: the fixture allow-list fails open when `FL_ENV` is unset. HIGH.**
   - Location: `services/worker/src/falcon_worker/main.py:54`. The code is `os.environ.get("FL_ENV", settings.fl_env)`, and `settings.fl_env` defaults to `"local"` (`packages/falcon_core/src/falcon_core/config.py:17`).
   - With `FL_ENV` unset and `FL_SSRF_ALLOW_HOSTS=fixtures`, `guard_policy().allow_hosts == {'fixtures'}`. Probe output:
     ```
     None settings.fl_env= local allow_hosts= ['fixtures']
     ''   ...                     allow_hosts= []
     'production' / 'prod' / 'PRODUCTION' / 'staging' -> allow_hosts= []
     ```
   - With FL_ENV unset, the new DNS-precheck skip (`engine.py:298`, `:307`) is live. Probe: `FL_ENV=None http://fixtures/official/ rendered=True []`, with NXDOMAIN and no `not_rendered`.
   - The commit message and the compose comment both say this follows the sandbox rule, but it does not. The sandbox uses `e.get("FL_ENV") in ALLOWLIST_ENVS` with no fallback (`services/sandbox/src/falcon_sandbox/settings.py:38`), so it fails closed on unset. The L1 must-check explicitly lists "unset".
   - Fix: read `os.environ.get("FL_ENV")` with no default. Add `FL_ENV` unset (`monkeypatch.delenv`) to `test_guard_policy_allow_hosts`; it currently tests only `production`, `staging` and `""`. Add a cascade-level test showing that with FL_ENV unset, an allow-listed host with NXDOMAIN is `not_rendered:dns_failure`.

2. **B2: the L1 decision is not implemented. A never-populated mirror must be `feed_disabled`, not `feed_unavailable`. HIGH (G1).**
   - `packages/falcon_core/src/falcon_core/signals/reputation/openphish.py:48-49` returns `feed_unavailable` when `hit.updated_at is None`. That error is degrading, so on a fresh clone with no private feed, every verdict is degraded and none can be `no_warning_signs`.
   - `packages/falcon_core/tests/cascade/test_cascade_tiers.py:156` (`test_t0_mirror_never_loaded_degrades`) asserts this degraded behaviour. It must be inverted.
   - L1 has decided: with no `feed:openphish:updated_at`, emit error `feed_disabled`. It is informational per `scoring/params.yaml:60` and `arbiter.py:229`, so it must not degrade.
   - Keep real outages degrading. A Redis exception in `FeedMirror.lookup` currently propagates into `_run_signal`, where it becomes error evidence and degrades. Keep it that way, and add a test proving a Redis `ConnectionError` still degrades.
   - Required tests:
     - (i) never-loaded mirror: `rep.openphish.error == "feed_disabled"`, `degraded is False`, and the benign demo URL can reach `no_warning_signs`.
     - (ii) stale mirror (>6 h) with no hit: not H2, not degraded (neutral evidence).
     - (iii) stale mirror with a hit: not H2, not degraded, risk evidence only. `test_t0_stale_feed_hit_is_not_h2` covers the H2 part; add `degraded is False`.
     - (iv) Redis error: degraded.
   - Update the DECISIONS.md entry (line 454) to record the L1 decision instead of "L1 to decide".

3. **B3: smoke check 3 leaves a synthetic "fresh mirror" behind. MEDIUM. Must fix because it interacts with B2.**
   - `scripts/smoke.py:136,139` runs `SADD` with the synthetic hashes and `SET feed:openphish:updated_at <now>`, then never undoes them.
   - DECISIONS.md says the next refresh tick restores the real state. That is only true when the feed dir is mounted and has a `last_poll_utc`/mtime; see `refresh_openphish` returning early at `mirror.py:239-244`.
   - On a fresh clone without private feed data, nothing restores it. After the fix in B2, `rep.openphish` would then report "Not listed in the OpenPhish feed mirror", fresh, for 6 h, against a mirror with no real feed in it. That overstates coverage.
   - Fix: smoke records the prior `updated_at` (and whether it existed), then in a `finally` it `SREM`s the synthetic hashes and restores or `DEL`s `updated_at`.
