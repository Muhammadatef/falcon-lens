## Findings

### Blocking
- **B1. CI never ran (merge conflict).** `gh pr checks 28` reports "no checks reported", and `git merge-tree` shows conflicts in `pyproject.toml` and `uv.lock`. Rebase onto current `origin/main`, re-lock, push, and get all CI jobs green.
- **B2. `make guard` fails, so CI's `check_no_live_urls.py` step will fail.** The non-defanged URLs are in `packages/falcon_core/tests/signals/test_page_signals.py`, at lines 79 (`api.telegram.org`), 81 and 123 (`discord.com`), 82 (`hooks.slack.com`), 83 (`formspree.io`), 84 (`webhook.site`) and 93 (`www.google-analytics.com`). These are service endpoints, not phishing URLs, but the repo rule and the guard apply to them. Either write them defanged and refang them in the test (as `evals/common.refang` does), or build the strings at runtime. Do not weaken the guard.
- **B3. The 5 MB size cap is applied only after the whole body is buffered.** At `browser.py:257-258`, `route.fetch(...)` and then `await resp.body()` read the entire response before `budget.add` runs at `:281`. Playwright's `Route.fetch` has no size option (signature: `headers, max_redirects, max_retries, method, post_data, timeout, url`), and `services/egress/src` has no byte cap (`grep max_bytes\|limit` returned nothing). A multi-GB or chunked response is therefore held in driver memory before the check, and the container limit is 2 GiB. Fix:
  1. Reject before reading the body when `content-length` exceeds the remaining budget.
  2. Add a test with a fixture that declares an oversized length.
  3. Open a follow-up card for builder-security: a per-tunnel byte cap in the egress proxy, because only that covers chunked bodies. Record the remaining chunked-body risk in DECISIONS until it lands.
- **B4. Tests are missing for three must-check behaviours.** I verified each by hand (see Checks run), but nothing in the suite pins them:
  1. `Settings.from_env()` with `FL_ENV=production` gives empty `allow_hosts`, and `check_target("http://falcon-demo-bank.test/")` then returns `internal_name`.
  2. `build_app(Settings(api_key=""))` returns 503 on `/render`, `/capture` and `/metrics`.
  3. The total timeout: a visit whose `_visit` sleeps past `TOTAL_TIMEOUT_S + 3` returns `timed_out=True` / `error="timeout"`. A patched or fake browser is enough.
- **B5. Egress refusals are reported as successful page loads.** For `http://10.0.0.1.nip.io/` the proxy logged `connect denied ... non-global address blocked`, and for `169.254.169.254.nip.io` it logged `dns resolution failed`. Yet `/render` returned `status=403, error=None, title='', visible_text=''`, with nothing in `network.blocked` (the same holds for https). So every egress denial, including every DNS failure for a dead phishing domain, reaches the cascade as a loaded, empty, form-free page. That can become "no warning signs" instead of a degraded verdict (CONTRACTS invariant 4). Fix: mark egress refusals so they can be told apart (for example a response header from the egress stub, or treating a proxy-originated 403 on CONNECT as a failure). Map them to `error="blocked_by_egress"` (or `"dns_failed"`) plus a `network.blocked` entry, and add an integration test using a `*.nip.io`-style host that resolves to a non-global address.
- **B6. The sandbox token defaults to a public value.**
  - `.env.example` defines `FL_SANDBOX_TOKEN` twice: line 46 (`fl_sandbox_demo_key`, the same as the *public judges* key on line 45) and line 56 (`change-me-sandbox`).
  - `settings.py:43` also falls back to `FL_SANDBOX_API_KEY` (the public judges key) when `FL_SANDBOX_TOKEN` is unset.
  - Together these mean the internal-only token can silently equal a value published in the public repo.
  - Fix: delete `.env.example:46`, remove the `FL_SANDBOX_API_KEY` fallback, and treat a blank or whitespace token as unset. A `" "` token is currently accepted: my TestClient call with key `" "` got through to `visit`.

### Should fix (not blocking)
- **S1. Duplicate page-evidence logic (flag for L1).**
  - `signals/page/classify.py` + `signals/page/evidence.py` + `signals/page/exfil.py` + `signals/visual/brands.py` here overlap with `falcon_core/cascade/page.py` on `feat/core-cascade` (PR #18): `field_kind`, `form_kinds`, `target_kind`, `claimed_brands` and `page_evidence` (page.cred_form, cross_origin_post, hotlinked_brand_assets, cloaking, brand.claimed_not_owned).
  - The two are not equivalent. #18 defangs origins (`_origin_defanged`) and uses the brand registry. #28 uses `BrandRef` / `FIXTURE_BRAND` and a heuristic `registrable_domain` (`signals/page/hosts.py`, not the PSL).
  - L1 picks one. The other PR then drops its copy and consumes the chosen module.
- **S2. Raw hostnames in evidence `observed`.** For example `page.cross_origin_post.observed.targets[].host = "falcon-bot-relay.test"`. For real phishing these are live domains in verdict output (CONTRACTS invariant 5). Defang them (as #18 does), or confirm that verdict assembly defangs them. This should be decided together with S1.
- **S3. The production check fails open.**
  - `settings.py:36` honours the allowlist for any `FL_ENV` other than exactly `production`, including `prod`, `PRODUCTION` and unset.
  - Invert it: honour `FL_SSRF_ALLOW_HOSTS` only when `FL_ENV` is in `{local, dev, test}`.
  - The sandbox's compose env also appends three hosts unconditionally (`...},falcon-demo-bank-cloak.test,falcon-demo-bank-injection.test,falcon-bot-relay.test`).
- **S4. `FL_SSRF_ALLOW_HOSTS` in `x-app-env` is unused.** It was added to api, worker and the other app services with the comment "Ignored when FL_ENV=production", but only `services/sandbox/.../settings.py:36-37` reads it. Remove it from `x-app-env` or wire it up deliberately; as it stands the comment misleads.
- **S5. Duplicate `exfil_targets`.** A live phish `/render` returned 5 identical `{origin: falcon-bot-relay.test, category: messaging_bot_api}` entries. De-duplicate by (origin, category).
- **S6.** `browser.py:6` has an unused `import base64  # noqa: F401`. Remove it.
- **S7. Proposed contract.** `contracts/page_features.schema.json` (from `RenderFeatures.model_json_schema()`) is L1's call. Until it exists, `/render` has no contract test.
- **S8. Notes for L1, carried from the PR body.**
  - `target_kind()` in #18 does not recognise `falcon-bot-relay.test`, so H4 needs `exfil_targets` in the demo.
  - The egress proxy is CONNECT-only, so plain `http://` sites cannot be fetched in production.
- **S9. `visible_text` must stay internal.** `/render` returns up to 4 KB of page text. That is correct for the worker-to-extractor path, but the public API and MCP must never pass it through (THREAT_MODEL "never return raw content"). The cascade PR should include a test for this.
