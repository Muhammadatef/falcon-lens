## Verdict: **CHANGES REQUESTED** (the fix is correct; it needs a rebase and a regression guard)

The bug is real, and its impact is bigger than the PR says. On current main, `docker compose --profile '*' config` resolves 4 variables to their comment text:

| Variable | Resolved value on main |
|---|---|
| `ANTHROPIC_API_KEY` | `# empty => local-only mode (same as sovereign)` |
| `GOOGLE_SAFE_BROWSING_API_KEY` | `# empty => feed disabled` |
| `URLHAUS_AUTH_KEY` | `# empty => feed disabled` |
| `TELEGRAM_BOT_TOKEN` | `# empty => alerts stay in Grafana + logs` |

`ANTHROPIC_API_KEY` is the serious one. The #19 router enables cloud on `bool(key)` (`llm/config.py:55-57`), so a fresh clone would send every LLM call to Anthropic with a bogus key, fail, fall back, and count `fl_llm_fallback_total` on every request. The GSB and URLhaus feeds would also count as "enabled" with a bad key.

On the branch, all 4 resolve to `""`. Every other variable is identical to main, apart from the rate limit noted below.

## Findings

1. **Blocking: rebase onto main.** There's a conflict in `.env.example`. Keep main's `FL_RATE_LIMIT_PER_IP_PER_MIN=60`; the branch value 30 is stale. Move any comments main added since.

2. **Blocking: add a regression guard.** The bug is already coming back: #19 adds `FL_BRANDS_PATH=                    # path to ...` (`.env.example:32` on `feat/core-agent`), which compose would read as the comment text. Add a check to `make guard` or a pytest that fails on `^[A-Z_]+=.*\s#` in `.env.example`. Ideally also run `docker compose config` in CI and assert that no resolved value starts with `#`.

3. **Non-blocking:**
   - The non-empty values with inline comments (`FL_ENV`, `OLLAMA_BASE_URL`, …) parsed correctly on main, because compose strips ` #…` after a non-empty unquoted value. Moving them anyway is fine for consistency.
   - Confirm that `GRAFANA_ADMIN_PASSWORD` reaches Grafana through `${…}` interpolation, since no service's `environment` lists it.

## Eval impact

None on detection metrics. It prevents a false cloud route and bogus "feed enabled" state on fresh clones, which would otherwise distort the cost and latency metrics and the share of LLM calls.
