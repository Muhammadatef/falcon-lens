# PR #55 fix/sandbox-interrupted-navigation (head 68c8431, base main 8ea5a1b)

**Verdict: APPROVE** (round 1)

## Reasons
1. Each hop goes through the policy. The context route handler (`browser.py:249-330`) runs `policy.decide` on every request: documents, subresources and JS/meta-refresh navigations. Each server redirect hop is fetched with `route.fetch(max_redirects=0)` (line 278), re-checked (300-305), and goes through the context proxy. A client-side chain A->B->10.x/metadata becomes a new top-level request and is refused before any bytes come back. The fix also re-checks `page.url` after settling (`settle_interrupted`, 366-382), which adds one more check.
2. It fails closed. A blocked top-level navigation sets `st.doc_blocked` (256-257), which gives `blocked_by_policy` both in the interrupted path (378-381) and in the normal path (434-435). A failed main navigation sets `st.nav_fail` (311-312, 316). If no document landed, `response` stays None and the result is `no_response` (438-439). I found no path where an error turns into an empty clean page.
3. The time budget still holds. The only new wait is one `wait_for_load_state(timeout=remaining_ms())`, and its timeout sets `timed_out`. Since `remaining_ms` never goes below 200 ms, the overrun is at most about 200 ms per wait. The hard deadline is the same as before.
4. The fixtures use only Falcon Demo Bank, carry the TEST FIXTURE banner, and point at a private IP (10.255.255.1). They contain no live URLs.

## Non-blocking (P2)
- P2-1 Tests: tests 1-2 cover the client-redirect path, but they also pass when Chromium's race does not happen. Tests 3-4 simulate the race with a monkeypatched `Page.goto`. There is no test with a two-hop client chain (A->B->private) and none with a 169.254.169.254 target.
- P2-2 `st.nav_response` keeps the most recent non-3xx main-frame response. That is correct here because `doc_blocked` and `nav_fail` gate it, but a comment saying so would help.
