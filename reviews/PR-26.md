## Must-checks

1. **All HTTP goes through the guarded client: PASS.** `domain/common.py:fetch_json` calls only `ctx.http.fetch(..., max_bytes=...)`. `reputation/external.py:_post_json` calls only `ctx.http.post` and never builds its own client. whoisit is deliberately not a dependency, because it does its own requests/httpx I/O (DECISIONS entry). The RDAP base URL comes from the IANA bootstrap and is also fetched through `ctx.http`, so registry hosts get the SSRF checks too. The `urllib.parse` imports are for parsing only.
2. **The feed mirror stores only sha256 and logs no URLs: PASS.**
   - `mirror.py:row_members` / `lookup_keys` emit only `_sha(...)` hex digests.
   - Host digests are added only for bare-path listings with no query.
   - The only log calls are `log.info("openphish mirror refreshed", extra={entries, rows, age_s})` and `log.warning(... exc_info=True)` on publish or refresh failure. Neither carries row URLs.
   - The `rep.openphish` evidence carries only `url_ref` = sha256[:16].
3. **Exact error strings: PASS.**
   - `feed_disabled` appears at `openphish.py` (`if not enabled`), `external.py run_gsb` and `external.py run_urlhaus`, with no network call before it.
   - `rdap_unsupported_tld` appears at `rdap.py run()` and is negative-cached for 1 h.
4. **crt.sh rate limit, backoff and size cap: PASS.**
   - A semaphore allows 2 concurrent queries (`crt.py:_semaphore`).
   - A 60 s circuit breaker trips on `rate_limited` / `timeout` / `connect_error` / `http_5xx` and then reports `crt_backoff`.
   - The response is capped at `MAX_JSON_BYTES = 4 MiB`, under the guard's 5 MB hard cap. Anything over the cap raises `SSRFBlocked(response_too_large)` and maps to `crt_ssrf_blocked:response_too_large`. It is never truncated.
5. **Caching TTLs: PASS against T-008.**
   - `rdap:<domain>` 24 h, negative (not_found / unsupported_tld) 1 h.
   - `rdap:bootstrap` 24 h.
   - `crt:<domain>` 6 h, negative 1 h. This is shorter than the card's 24 h, which is the conservative direction and is documented in the crt.py docstring.
   - GSB and URLhaus 300 s.
   - Every lookup is single-flighted (`cache.py:single_flight`, shielded task).
6. **No live phishing URLs in tests: PASS.** I listed every URL in the new tests and fixtures. Phishing-like hosts are all on `.test` (`fake-bank-login.test`, `bare-host-phish.test`, `shared-host.test`, `ancient-phish.test`) or `203.0.113.9` (TEST-NET-3). The rest are mocked API endpoints, invented demo hosts or `example.com`.
7. **Builder edit to `scripts/check_no_live_urls.py` REVIEWED_TEST_HOSTS: ACCEPTED, with F1.** I checked each added host:
   - `crt.sh`, `data.iana.org` and `safebrowsing.googleapis.com` are the real public API endpoints. Tests mock them and never fetch them, and they never serve phishing.
   - `falcon-demo-shop.com`, `falcon-demo-shop.ae`, `falcon-demo-other.com` and `another-demo-site.net` are invented and only used as lookup subjects against fakes.

## Follow-ups (non-blocking)

- **F1 (low, test hygiene).** `tests/signals/test_domain_rdap.py:72` uses `another-demo-site.net`, and `test_domain_crt.py:82` uses `falcon-demo-other.com`. Both sit on real, registrable TLDs that a third party (including a phisher) could register later.
  - Change `another-demo-site.net` to a reserved name such as `another-demo-site.test` or `demo.example`.
  - Do the same for `falcon-demo-other.com` where the test doesn't depend on the TLD.
  - Then drop them from REVIEWED_TEST_HOSTS.
  - `falcon-demo-shop.com` / `.ae` can stay only where the test needs a real ICANN TLD for PSL or bootstrap routing.
- **F2 (medium, must fix before any key is set): wire to the PR #16 `GuardedHTTPClient.post`.** main's `post(url, *, json=, data=, max_bytes=, timeout=)` has **no `headers` parameter**.
  - `external.py run_urlhaus` passes `headers={"Auth-Key": key}`. With a key set, that raises a TypeError, which `async_signal` turns into an error evidence: the signal degrades but does not crash.
  - Agree a header-capable POST with builder-security, or another way to send the URLhaus auth key.
  - The production `GuardPolicy.post_allow_hosts` must contain exactly `safebrowsing.googleapis.com` and `urlhaus-api.abuse.ch`.
  - Add a test that runs against the real `GuardedHTTPClient.post` signature, not only a fake.
- **F3 (medium, before enabling GSB).** `external.py run_gsb` puts the API key in the query string (`f"{GSB_URL}?key={key}"`).
  - `_post_json` maps SSRFBlocked/FetchFailed to the reason code only. But any other exception reaches `async_signal`, which writes `f"{type(exc).__name__}: {exc}"` into `Evidence.error`, and that string goes back to callers. URL-bearing exception text could leak the key there.
  - Prefer the `X-Goog-Api-Key` header once F2 lands. Until then, catch `Exception` in `_post_json` and return a fixed code.
- **F4 (low, correctness).** The GSB cache key `gsb:{host_ascii}{path}` drops the query, so a cached miss for `/a?x=1` is reused for `/a?x=2`. Use the sha256 of the canonical URL (which also keeps plaintext out of Redis). `run_gsb` also doesn't check `c.ok` before using `c.url`, unlike `run_urlhaus`.
- **F5 (low).** The arbiter must treat `feed_disabled` as "not configured", not "degraded", as the DECISIONS entry proposes. Track this in T-011.
