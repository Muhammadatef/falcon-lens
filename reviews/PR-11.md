## Findings
1. **P1: the S-rule is scoped too broadly.** `pyproject.toml` `[tool.ruff.lint.per-file-ignores]` contains `"services/sentinel/**" = ["E501", "S311", "UP047"]`. That disables S311 for `services/sentinel/src/falcon_sentinel/**` and `sentinel_core/**`, where the ULID and incident-id code lives. Today it hides one legitimate hit (fixtures.py:42), but it would silently hide any future non-crypto `random` in the incident-id path. That breaks the rule that S-rules stay on in production code. Fix: use `"**/fixtures.py" = ["S311"]`, which is what #10 does.
2. **P2: the E501 ignores are dead or too wide.** `"services/sentinel/**" E501` and `"packages/falcon_core/src/falcon_core/signals/**" = ["E501"]` match zero production lines at 120. The only E501 hit is in a test file. Fix: drop both and put E501 under `**/tests/**`, as #10 does. UP047 can be ignored globally (it is not a security rule), again as #10 does.
3. **P1: supply chain.** `.github/workflows/ci.yml:64` `uses: aquasecurity/trivy-action@v0.36.0`, and every other action, is pinned to a mutable tag. #10 pins every action to a commit SHA and installs trivy from a pinned release. Prefer #10's version.
4. **Overlap.** #10 (green on its own CI, 0 behind main) already contains everything else in this PR: ruff 120, repo-wide format, `types-PyYAML` and the runtime deps, and mypy scoped to `falcon_core/src` (plus `explicit_package_bases`). The `scripts/**` S603/S607 ignores are replaced there by line-level `# noqa`, which is narrower. The only thing unique to #11 is commit `0d66978` (`.gitattributes` union merge for DECISIONS/STATUS/TASKS). That commit is fine and I would approve it on its own.
