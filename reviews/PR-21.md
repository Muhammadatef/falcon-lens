## Must-checks

- **Phishing is hashes-only: OK.** `evals/manifests/phishing.manifest.jsonl` keys are `{url_sha256, registrable_domain_sha256, first_seen, feed}`. `corpus.py:125-170` only emits `verdict.created` events with a `sha256-…` domain. These events never go to the API.
- **source=replay: OK.** `common.py:88` sends `X-Falcon-Source: replay` on every call. The API (`services/api/src/falcon_api/app.py:251-253`) honours the header only for authenticated callers, and seed/replay send `FL_SANDBOX_API_KEY`. All events set `source` (`corpus.py:159`, `replay.py:91`).
- **No secrets printed: OK.** `load_env` never echoes values. `ApiError` messages carry only the status and path. The key is never interpolated into output.
- **Caddy XFF spoofing: OK.** The gateway publishes only on `127.0.0.1` (`docker-compose.yml:88`) and the API publishes no host port. Public traffic therefore arrives only via cloudflared, and the Cloudflare edge overwrites `Cf-Connecting-Ip`. `header_up X-Forwarded-For {client_ip}` replaces the header rather than appending to it. The API takes the last XFF hop, and only from private peers (`app.py:83-95`). Local processes can still set the client IP, which is acceptable because they are trusted.
- **Rate-limit guidance: OK.** replay warns when `RATE*60 > FL_RATE_LIMIT_PER_IP_PER_MIN` (`replay.py:210-216`). seed paces at 0.4/s and honours `Retry-After`, capped at 65 s (`common.py:184-193`).
- **tunnel-stop kills only its recorded pid: OK, with a hardening note (N1).**
- **demo-reset only wipes its own project's volumes: FAIL (B1).**
- **No live phishing URL ever sent to the API: holds for today's data, but not by construction (B2).**

## Blocking findings

1. **B1 (high): `make demo-reset` can delete another stack's volumes.** At `Makefile:4`, `PROJECT = $${COMPOSE_PROJECT_NAME:-falcon}` reads only the shell environment. Docker Compose also reads `COMPOSE_PROJECT_NAME` from `.env`.
   - Reproduced: with `COMPOSE_PROJECT_NAME=falcon2` in `.env`, `docker compose config` gives project `falcon2` and volume `falcon2_pg_data`. The Makefile still runs `docker volume rm -f falcon_pg_data falcon_redis_data`.
   - Result: `down` stops `falcon2`, then the command deletes the *default* stack's Postgres and Redis data. It succeeds whenever that stack is stopped. The confirmation prompt also shows the wrong names.
   - Fix: derive the name from Compose itself, e.g. `P=$$(docker compose config --format json | python3 -c 'import json,sys;print(json.load(sys.stdin)["name"])')`, and use `$$P` in both the prompt and `volume rm`. Alternatively, resolve the volumes with `docker compose config --format json` → `.volumes.pg_data.name`.
   - Add a test, or at least a dry-run `ECHO=1` path that is checked in CI, asserting that the resolved names follow `.env`.

2. **B2 (high, defensive-only): red-team and message corpora are refanged and sent to the live API without a host allowlist.**
   - `corpus.py:109` runs `refang()` on any red-team URL value. `corpus.py:113-122` forwards human or synthetic message text verbatim, and the API extracts and fetches the URLs in that text.
   - CLAUDE.md:63 allows committed files to hold *defanged real* URLs. A defanged phishing URL in `evals/redteam/cases.jsonl` or a `human_messages*.jsonl` would therefore be refanged and detonated by `make seed`. That breaks the "no live phishing URL ever sent to the API" rule. The rule holds today only because those files do not exist yet.
   - Fix:
     - (a) Never refang outside the `legit` group.
     - (b) Drop any red-team URL, or any message containing a URL or bare domain, whose host is not on the fixture allowlist (`*.test`, `*.example`, `*.invalid`). Report the skipped count in the summary without printing the value.
     - (c) Add tests: a defanged non-fixture red-team URL and a message with a real-looking domain are both excluded.

## Non-blocking (fix in this PR if cheap)

- **N1: `tunnel-stop` and `tunnel` check pid liveness only** (`ops.py:163-166`, `ops.py:206-208`). If cloudflared crashed and the pid was recycled, `tunnel-stop` sends SIGTERM to an unrelated process, and `tunnel` reports a false "already running". Before signalling, check that `ps -p <pid> -o comm=` contains `cloudflared`. A non-integer pid file raises `ValueError`; handle it by treating the file as stale.
