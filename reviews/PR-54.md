Playwright's `route.fetch` tunnels **both** http and https through CONNECT. When CONNECT fails, the proxy's own 403 and its headers are replayed to the caller, so `X-Falcon-Block-Reason` reaches `proxy_refusal` on both schemes.

## Security questions from L1

1. **Can a malicious target make a real proxy or SSRF block look like `http_403_empty` (soft)?** No. Every proxy refusal that comes from a policy decision goes through `_deny` (`services/egress/src/falcon_egress/main.py:110-114`), and `_deny` always writes `403` + `X-Falcon-Block-Reason`. That covers CONNECT denial (`:186`), plain-HTTP denial (`:222`) and absolute-form https (`:174`). The proxy's other replies carry no header but never become `http_403_empty`, because that code needs status 403:
   - 405 for a non-GET method (`:206`) gives `egress_blocked`.
   - 502 on dial failure or dial timeout (`:193`, `:229`) gives `egress_error`.
   - 400 and 431 (`:149,155,165,176,181,213,216`) give `None`, which is pre-existing (see N2).
   - A head-read timeout closes the socket with no reply (`:151-153`). That is a transport error, and `classify_fetch_error` never maps it to a 403.

   The other cases are also covered:
   - **Redirects to blocked hosts:** main-frame hops go back to the visit loop. It re-checks them with `policy.decide` (`browser.py:367-377`, `blocked_by_policy`), and then `go()` sends the request through the proxy, which adds the header.
   - **Subresource redirects:** `browser.py:292-298` records them as blocked.
   - **Subresources:** `proxy_refusal` runs only when `main_nav` is set (`browser.py:306`), so a subresource cannot set the page error.
   - **The target's response:** a target response relayed through the tunnel can only be the target's own 403. Calling that `http_403_empty` is correct.
2. **Forged header.** Confirmed fail-safe. A target that sends `X-Falcon-Block-Reason` gets `blocked_by_policy[:x]`, which is hard (degrades). A value that is not a clean token becomes bare `blocked_by_policy` (`policy.py:116-118`, `_REASON_RE.fullmatch`). The tests cover empty, whitespace, punctuation, overlong and non-ASCII values (`test_limits.py:139-141`). The reason is restricted to `[a-z0-9_]{1,40}`, so a target cannot inject anything through the error string.
3. **API-level 400 `blocked` for 169.254.169.254.** It is treated as hard:
   - `HttpSandboxClient.render` raises `SandboxError("http_400")` for any status that is not 200 (`packages/falcon_core/src/falcon_core/cascade/ports.py:62-63`).
   - `http_400` is not in PR #52's `SOFT_RENDER_FAILURES` (`timeout, dns_failure, tls_error, http_403_empty, empty_response`), so it degrades. It also degrades on main (`engine.py:468-477`).
   - In the real cascade the metadata IP is stopped even earlier, at the worker's T0 SSRF guard (`engine.py:303-305`, `run.blocked`, `not_rendered:metadata`), so it never reaches the sandbox.
4. **mypy.** The errors are pre-existing and do not touch CI. `browser.py` is unchanged by this PR (`git diff --stat` is empty), and `origin/main` gives the same 4 errors. They are **3** unused `type: ignore` comments (`browser.py:203,212,347`) plus **1** `attr-defined` (`Image.LANCZOS`, `browser.py:80`), not 4 unused ignores. CI `typecheck` passes because `services/sandbox/src` is not listed in `[tool.mypy].files` (`pyproject.toml:89`).

## Findings

### Blocking

1. **SSRF and limit integration tests were deleted without a reason** (`services/sandbox/tests/test_integration.py`, diff hunk at old lines 142-167). The PR body and the commit message do not mention it. These tests were removed:
   - `test_internal_targets_refused`, which covered `redis:6379` and `10.0.0.1`. Only the metadata IP is kept.
   - `test_private_subresources_recorded_and_blocked`. Its fixture `services/fixtures/sites/official/blocked-assets.html` still exists, and no other test checks subresource SSRF blocking against the real stack.
   - `test_redirect_cap_stops_at_ten`. Its fixture is `services/fixtures/conf/redirs.inc`. `test_unit.py:66` only covers the policy function, not the end-to-end `final_url is None`.
   - `test_egress_refusal_or_dns_failure_is_an_error_not_an_empty_page`, which covered the **https** proxy-denial path and the proxy DNS-failure path.

   None of these behaviours is changed by the PR except the last one, whose expected codes are now `blocked_by_policy:*`. **Fix:** restore the first three tests unchanged. Update the last one rather than delete it: assert that `hxxps://localtest[.]me/` gives a code starting with `blocked_by_policy:`, that the nonexistent host gives a hard code (`blocked_by_policy:dns_failure`), and that `final_url is None`. The https case is the main path for real phishing links and needs end-to-end coverage. Then re-run the isolated-stack integration suite and paste the pass count.

### Non-blocking (for L1 / follow-up)

- **N1 (interaction with #52):** when the proxy itself fails to resolve a name, the result is now `blocked_by_policy:dns_failure`, which is hard under #52. It is no longer the soft `dns_failure`. This fails closed, and T0 usually catches unresolvable hosts first. L1 should still decide this deliberately when reconciling #52, because the old integration test expected `dns_failure`. If L1 wants it soft, #52 should map `blocked_by_policy:dns_failure` explicitly. The sandbox should not guess.
- **N2 (pre-existing, P2):** the proxy's own 400 and 431 replies (`main.py:149-216`) have no header and an empty body, so `proxy_refusal` returns `None` and the page is fulfilled as an empty 400. A browser-generated GET cannot reach these replies through Playwright, so this is not exploitable, but it is not fail-closed. Suggested fix: the egress proxy adds `X-Falcon-Block-Reason: bad_request` to every reply it generates itself.
- **N3 (pre-existing, P2):** `services/sandbox/src` is not type-checked in CI (`pyproject.toml:89`), and it has 4 mypy errors. This needs a separate card. It is not in this PR's scope.
- **N4:** the probe shows that Playwright uses CONNECT for plain http too, so the `405/407 -> egress_blocked` branch (`policy.py:99`) is effectively unreachable. It is harmless defence in depth and can stay.
