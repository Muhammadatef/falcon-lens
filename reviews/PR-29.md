## Findings

### Blocking
- **B1. CI never ran (merge conflict).** `gh pr checks 29` reports "no checks reported". There are conflicts in `Makefile`, `pyproject.toml` and `uv.lock`. The branch also still carries PR #7's content (`legit_urls.csv`, `collect_legit_urls.py`, `scripts/qwen_task.py` and its tests, `evals/specs/synthetic_messages_v2.json`), which main now has as the squash `7e52a88`. Rebase onto `origin/main` so that content drops out of the diff, re-lock, push, and get CI green.
- **B2. `fit.py` can train on test items, and the result would pass the harness.**
  - `fit.load_items` (`fit.py:51-54`) blocks the *name* `test`, but takes membership from the private cache (`load_private_items()`). `main()` never checks that cache against the committed manifest and lock.
  - I relabelled the 140 test rows as `train` in a scratch cache. `fit --dry-run` exited 0, and `load_items(('train',))` returned 566 (426 + 140).
  - `fit.py:221` writes `dataset_hash = load_lock_dataset_hash()`, the lock's hash, not a hash of the data actually used. So a model fitted on a stale or edited cache carries the "right" dataset hash, and once the cache is restored it passes `run.py:231`.
  - Fix: at the start of `fit.main()`, run the same checks as `run.py:219-227`: `check_rows(read_jsonl(ITEMS_MANIFEST), load_lock())` must be clean, and `{item_id: split}` from the private cache must equal the manifest. Also compute `dataset_hash` from the loaded items (`id:label:split`) and assert that it equals the lock.
  - Add a test that a cache whose splits disagree with the manifest makes fit exit non-zero.

### Should fix (not blocking)
- **S1. `t1_model.py:60-67`.**
  - TOCTOU: the code hashes `blob`, then `joblib.load(d / MODEL_FILE)` reads the file again. Load the verified bytes instead (`joblib.load(io.BytesIO(blob))`).
  - The sha256 is compared against a sibling file in the same directory. That catches corruption and feature-set drift, but anyone who can swap the pickle can also swap the meta. The real control is review plus reproducibility, which I confirmed (a byte-identical refit).
  - Reword the `ModelError` docstring ("tampered with") so it does not overclaim. Optionally pin `model_sha256` in `params.yaml` `fit:` as well, so a model swap shows up in the scoring diff.
- **S2. Test FPR misses the target.** Test FPR is 0.0375 (CI [0.0, 0.082377]) against the 2% target, and test precision is 0.951613. The PR reports this honestly. L1 and docs must not claim the FPR target is met; only validation (0.011905) is under 2%.
- **S3. Two constants appear among measurements.**
  - `run.py:177` `cost_per_check_usd.T1_offline: 0.0`.
  - `run.py:149` `recall_blocklist_only_baseline: 0.0`. This is emitted only when zero-day items exist, which is not the case today.
  - Both are true by construction, not measured. Mark them as such (for example `{"value": 0.0, "basis": "by construction: no metered calls"}`) so nobody reads them as a measurement. Neither appears in the published JSON.
- **S4. Test the params diff.** Add a test that the shipped `params.yaml` differs from `tests/scoring/params_draft.yaml` only in `bands.tau_*`, `cascade.eps_*`, `fit` and `draft`. That holds now (checked above), but nothing enforces it.
- **S5. The gate ignores dataset changes.** It does not compare the baseline's `dataset_hash` with the result's. After a dataset rebuild it compares different data silently. Print a notice, or require `make eval-baseline` when they differ.
- **S6.** `evals/manifests/phishing.manifest.jsonl` still holds unkeyed sha256 (acknowledged; follow-up for the collector owner).
- **S7. For L1.** Update the "draft values" wording in SCORING.md. Ask infra to scrape `evals/results/latest.prom`. Note that nothing in the runtime loads the T1 model yet (`grep t1_model services packages/falcon_core/src` finds only the loader), so the worker's T1 still uses the draft classifier until it is wired up.
