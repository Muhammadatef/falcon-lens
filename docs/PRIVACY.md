# PRIVACY (handling description; not a legal compliance claim)

- **What we store.** The sha256 of the canonical input, a defanged copy of each link checked, the evidence and the verdict. What a person pastes is **not** stored as such, and message and email bodies are not stored unless the user opts in to "report this".
- **Links that carry personal data.** A link can hold the recipient's details (`?email=…`, a phone number, an ID). The page is checked at the full address, but the copy that is stored, returned by the API and shown (`canonical_url`) has everything after the host passed through the same redaction as below, also when percent-encoded, and the fragment is dropped. Not covered yet: addresses inside evidence details (redirect chain, links found in a message) are defanged but not redacted.
- **Redaction** is applied to text before any cloud LLM call. Logs are separate: they escape control characters and carry no message bodies. Redaction covers UAE phone numbers (+971 and 05x), Emirates ID (784-YYYY-NNNNNNN-N), card numbers (Luhn-checked), emails and IBANs (AE..).
- **Cloud mode.** Redacted, spotlighted text goes to the Anthropic API for extraction, investigation and responses. Nothing else leaves the machine except lookups: RDAP, crt.sh and feeds, which carry domain names only.
- **Sovereign mode.** Every LLM call goes to the local Ollama, so no content leaves the machine. Lookups are still domain-only, and they can be disabled with `FL_OFFLINE_LOOKUPS=true`.
- **Retention.** A retention policy is planned (verdicts kept for a limited period, then aggregated) but it is **not yet automated**. The audit log is append-only. Snapshots are local only.
- **The product never asks for** personal, banking or ID details.
- **Public read-only until SSO (owner decision 24 Nov).** `/history`, `/checks/[id]` and `/incidents/[id]` open without a key. They are served by Next.js routes that call the API server-side with a `read`-scope key and pass every payload through an allow-list (`web/lib/public-history.ts`). **Shown:** for links the defanged host only (nothing for messages, emails and images), verdict, risk score, tiers run or skipped, evidence codes with their display text, reasons text, tool names and latency; for incidents the title, severity, status, counts, defanged domains, Sentinel node names, timestamps and action types with status. **Never shown:** raw input, full URLs, paths, queries, userinfo, evidence `observed` values, email headers or addresses, phone numbers (any free text is scrubbed of links, addresses and numbers), draft bodies, recipients, approver names. Approve and reject stay on `/ops`, which needs an operator key. Replayed and synthetic rows are labelled. Permissions and per-user views come with SSO.
- **Voice (hands-free "Hey Falcon").** Voice audio is processed locally and discarded. The browser sends one short clip (max 15 s, 1 MB) to our API, which passes it to a Whisper model running on our own machine (native Mac process, or the `voice` container). The audio is held in memory only: never written to disk, never stored, never sent to a cloud service, never logged. The transcript is returned to the caller and, only when no keyword rule matches, also sent to the local embedding model (qwen3-embedding on this machine, via Ollama) to find the nearest scam-safety FAQ question; it goes nowhere else: it is not logged, not stored and not a metric label (metrics carry only wake, intent, language and engine codes). Wake phrase and intent are decided by fixed rules, not by a model. The voice container has no direct internet access; its only outbound traffic is the one-time download of the open Whisper weights through an allowlisting proxy (huggingface.co and hf.co). The per-address limit is 30 requests a minute.

## Voice cloning and spoken clips
- The voice assistant plays **pre-generated clips** (`web/public/voice/<lang>/`); no text typed by a user is sent to any TTS engine at runtime.
- Only the English clips made with Kokoro (Apache-2.0) are committed (`web/public/voice/en/`). Arabic clips spoken by Amazon Polly `Zayd` (generated once, offline, from our own script text only; no user data is sent to AWS, and nothing calls AWS at runtime) and every clip cloned from a real person's voice stay private: they live only in `data/private/voice/clips/<lang>/` (gitignored), are mounted read-only into the live stack's web service and are never committed (a test rejects `macos` and clone manifests inside the repo). A cloned clip needs that person's explicit, documented consent (also required by the SILMA and Chatterbox terms of use) and is generated from a reference recording kept at `FL_VOICE_REF_AR_AE` (default `data/private/voice/ref_ar_ae.wav`, gitignored). Withdrawal of consent means deleting the reference and the clips and regenerating.
