# submission/

Generated by `make submission` (see `scripts/submission/build.py`). Nothing here is edited by hand. The owner's deliverables (the card, the demo script, the deck and its PDF, and their generators in `build/`) are committed so they can be reviewed; every other output stays out of git and is rebuilt for the commit that is submitted.

| File | Form field or use |
|---|---|
| `title.txt` | Title |
| `description_en.txt`, `description_ar.txt` | Description, two to four sentences, at most 600 characters each (checked) |
| `tools_used.txt` | Tools used, generated from `uv.lock`, `web/pnpm-lock.yaml` and `docker-compose.yml` |
| `repo_url.txt` | Repository link |
| `PROJECT_CARD.md` | Exact copy-paste answer for every form field (title, both descriptions with measured lengths, generated Tools Used, repository, team, placeholders for the presentation link and the video URL). Source: `build/project_card.py` |
| `DEMO_SCRIPT.md` | Second-by-second script for the one-minute video (English and Arabic lines), the two-minute backup, the pre-recording checklist, do and do not. The results line is filled from the artifact. Source: `build/demo_script.py` |
| `FalconLens_ScamShield.pptx`, `FalconLens_ScamShield.pdf` | The presentation: twelve slides, 16:9, Night palette, Readex Pro, bilingual titles, speaker notes on every slide. One layout is written to both files by `build/build_deck.py`. Import the .pptx into Google Slides |
| `description.pdf` (source: `description.html`) | Description document, two to four pages |
| `architecture.png` | Still render of `docs/assets/architecture.svg`, embedded in the deck and the PDF |
| `CHECKLIST.md` | Every form field, file sizes, detected capabilities, owner checks |

Visual QA of the deck without PowerPoint: `uv run --with-requirements scripts/submission/requirements.txt python submission/build/build_deck.py --qa-dir /tmp/qa` writes one PNG per slide and fails on any text that overflows its box.

Rules the build enforces:

- A feature is described as working only when its capability is detected in the checkout (`scripts/submission/capabilities.py`). Anything else is marked PLANNED and listed on the roadmap.
- Every number in the deck (slides and speaker notes), the demo script, the PDF, the architecture diagram text, the README and `docs/DEMO.md` must be a metric value of the newest file in `evals/results/published/` (`scripts/submission/check_numbers.py`). Digits inside a hash or a timestamp do not count, a percentage is never allowlisted, and a speed claim passes only from the artifact or as a labelled design budget. With no artifact the results slide says "Evaluation in progress".
- The word "safe" never appears, and nothing implies a relationship with Abu Dhabi Police.

For the real submission run `SUBMISSION_STRICT=1 make submission`: it fails unless the end-to-end check is shipped.

The build needs Chromium for Playwright once: `uv run --with-requirements scripts/submission/requirements.txt playwright install chromium`.
