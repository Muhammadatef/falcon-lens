# submission/

Generated by `make submission` (see `scripts/submission/build.py`). Nothing here is edited by hand, and the outputs are not committed: they describe one commit and are rebuilt for the commit that is submitted.

| File | Form field or use |
|---|---|
| `title.txt` | Title |
| `description_en.txt`, `description_ar.txt` | Description, two to four sentences, at most 600 characters each (checked) |
| `tools_used.txt` | Tools used, generated from `uv.lock`, `web/pnpm-lock.yaml` and `docker-compose.yml` |
| `repo_url.txt` | Repository link |
| `deck.pptx` | Deck, eleven slides, Night theme |
| `description.pdf` (source: `description.html`) | Description document, two to four pages |
| `architecture.png` | Still render of `docs/assets/architecture.svg`, embedded in the deck and the PDF |
| `CHECKLIST.md` | Every form field, file sizes, detected capabilities, owner checks |

Rules the build enforces:

- A feature is described as working only when its capability is detected in the checkout (`scripts/submission/capabilities.py`). Anything else is marked PLANNED and listed on the roadmap.
- Every number in the deck, the PDF, the architecture diagram text, the README and `docs/DEMO.md` must be a metric value of the newest file in `evals/results/published/` (`scripts/submission/check_numbers.py`). Digits inside a hash or a timestamp do not count, a percentage is never allowlisted, and a speed claim passes only from the artifact or as a labelled design budget. With no artifact the results slide says "Evaluation in progress".
- The word "safe" never appears, and nothing implies a relationship with Abu Dhabi Police.

For the real submission run `SUBMISSION_STRICT=1 make submission`: it fails unless the end-to-end check is shipped.

The build needs Chromium for Playwright once: `uv run --with-requirements scripts/submission/requirements.txt playwright install chromium`.

## Part B documents (committed, generated by `submission/build/`)

| File | What |
|---|---|
| `FalconLens_Project_Description.docx` and `.pdf` | Project description for the judges: Arabic summary, then the English body, layer by layer, agents, security, privacy, results, integration, limits, glossary, team |
| `FalconLens_Cookbook.pdf` | Hands-on guide for a technical teammate: setup, every `make` target, recipes, PR flow, troubleshooting |

Rebuild (and check) with:

```bash
uv run --no-project --with playwright==1.65.2 python -m playwright install chromium   # once
uv run --no-project --with-requirements submission/build/requirements.txt --with pyyaml python submission/build/build_all.py
```

`build_all.py` regenerates both documents from `docs/`, the lockfiles and `evals/results/published/**`, then runs
`submission/build/check.py`: every number must trace to a published artifact, the product word for "harmless" must
never appear (English or Arabic), no email addresses, picture alt text, outline and 20 MB limit, and every command and
path in the cookbook must exist (`verify_cookbook.py`). The `.pdf` of the description is rendered from the same blocks as
the `.docx` through Chromium; the `.docx` has a table of contents field that Word fills when the file is opened.
